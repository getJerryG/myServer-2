# 业务流程

## 1. 概述

本文档描述了狼人杀赛事平台的核心业务流程，包括赛事创建与管理、赛事报名、赛程安排、比赛执行等关键流程。每个流程都包含流程图和详细的文字说明，以便于理解和实现。

## 2. 赛事创建与管理流程

### 2.1 流程描述

赛事创建与管理流程是指赛事管理员创建、编辑、发布和管理赛事的完整流程。

### 2.2 流程图

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  登录系统        │────▶│  进入赛事管理页面 │────▶│  点击创建赛事按钮  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  填写赛事信息     │────▶│  保存赛事信息     │────▶│  发布赛事        │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  赛事状态变为报名中  │────▶│  管理赛程安排     │────▶│  管理报名信息     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  赛事开始        │────▶│  赛事进行中      │────▶│  赛事结束        │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 2.3 详细步骤

1. **登录系统**：赛事管理员使用微信登录系统，获取管理员权限
2. **进入赛事管理页面**：管理员登录后，进入赛事管理页面
3. **点击创建赛事按钮**：管理员点击创建赛事按钮，进入赛事创建页面
4. **填写赛事信息**：管理员填写赛事名称、类型、规则、开始时间、结束时间等信息
5. **保存赛事信息**：管理员保存赛事信息，系统将赛事状态设置为"未开始"
6. **发布赛事**：管理员发布赛事，系统将赛事状态设置为"报名中"
7. **管理赛程安排**：管理员为赛事安排赛程，包括轮次、比赛时间、版型等
8. **管理报名信息**：管理员审核用户的报名信息，决定是否通过
9. **赛事开始**：到了赛事开始时间，系统将赛事状态设置为"进行中"
10. **赛事进行中**：赛事进行中，管理员可以管理赛程和比赛
11. **赛事结束**：赛事结束后，系统将赛事状态设置为"已结束"

## 3. 赛事报名流程

### 3.1 流程描述

赛事报名流程是指用户浏览赛事、查看赛事详情、提交报名信息并等待审核的完整流程。

### 3.2 流程图

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  登录系统        │────▶│  浏览赛事列表     │────▶│  查看赛事详情     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  点击报名按钮     │────▶│  填写报名信息     │────▶│  提交报名信息     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  报名状态变为待审核  │────▶│  等待管理员审核   │────▶│  审核结果通知     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐
│  审核通过        │────▶│  获得参赛资格     │
└─────────────────┘     └─────────────────┘
          │
          ▼
┌─────────────────┐     ┌─────────────────┐
│  审核拒绝        │────▶│  报名失败        │
└─────────────────┘     └─────────────────┘
```

### 3.3 详细步骤

1. **登录系统**：用户使用微信登录系统
2. **浏览赛事列表**：用户浏览平台上的赛事列表
3. **查看赛事详情**：用户点击感兴趣的赛事，查看赛事详情
4. **点击报名按钮**：用户点击报名按钮，进入报名页面
5. **填写报名信息**：用户填写报名信息，如队伍名称、队员信息等
6. **提交报名信息**：用户提交报名信息，系统保存报名记录
7. **报名状态变为待审核**：系统将报名状态设置为"待审核"
8. **等待管理员审核**：用户等待管理员审核报名信息
9. **审核结果通知**：管理员审核完成后，系统通知用户审核结果
10. **审核通过**：如果审核通过，用户获得参赛资格
11. **审核拒绝**：如果审核拒绝，用户报名失败

## 4. 赛程安排流程

### 4.1 流程描述

赛程安排流程是指赛事管理员为赛事安排赛程，包括轮次、比赛时间、版型等信息的流程。

### 4.3 详细步骤

2. **点击赛程管理按钮**：管理员点击赛程管理按钮，进入赛程管理页面

8. **填写比赛信息**：管理员填写比赛时间、所需玩家数、版型等信息
9. **保存比赛信息**：管理员保存比赛信息
10. **重复安排其他比赛**：管理员重复以上步骤，安排其他比赛
11. **发布赛程**：管理员发布赛程，赛程信息对所有用户可见

## 5. 比赛执行流程

### 5.1 流程描述

比赛执行流程是指比赛从开始到结束的完整流程，包括比赛准备、进行中、结束和结果处理等阶段。

### 5.2 流程图


### 5.3 详细步骤

2. **玩家进入房间**：玩家进入指定的比赛房间，准备开始比赛
3. **比赛开始**：到了比赛时间，比赛正式开始
4. **比赛进行中**：比赛进行中，系统记录比赛数据
5. **记录比赛数据**：系统实时记录比赛数据，如玩家发言、投票等
6. **比赛结束**：比赛结束，系统停止记录数据
7. **计算比赛结果**：系统根据比赛数据计算比赛结果
8. **更新选手积分**：系统根据比赛结果更新选手积分
9. **更新赛事排名**：系统根据选手积分更新赛事排名

11. **进入下一轮比赛**：如果还有下一轮比赛，系统准备进入下一轮

## 6. 用户登录与认证流程

### 6.1 流程描述

用户登录与认证流程是指用户使用微信登录系统，获取访问权限的流程。

### 6.2 流程图

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  用户打开小程序    │────▶│  点击登录按钮     │────▶│  调用微信登录API  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  获取微信code     │────▶│  调用后端登录接口  │────▶│  后端调用微信API  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  获取openid和session_key │────▶│  检查用户是否存在   │────▶│  创建或更新用户信息  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  生成JWT令牌      │────▶│  返回登录结果     │────▶│  保存令牌并登录成功  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 6.3 详细步骤

1. **用户打开小程序**：用户打开狼人杀小程序
2. **点击登录按钮**：用户点击登录按钮，请求登录
3. **调用微信登录API**：小程序调用微信登录API，获取登录凭证
4. **获取微信code**：小程序获取微信返回的code
5. **调用后端登录接口**：小程序将code发送到后端登录接口
6. **后端调用微信API**：后端使用code调用微信API，获取openid和session_key
7. **获取openid和session_key**：后端从微信API获取openid和session_key
8. **检查用户是否存在**：后端检查数据库中是否存在该openid对应的用户
9. **创建或更新用户信息**：如果用户不存在，创建新用户；否则更新用户信息
10. **生成JWT令牌**：后端生成JWT令牌，包含用户ID和角色信息
11. **返回登录结果**：后端返回登录结果，包含JWT令牌
12. **保存令牌并登录成功**：小程序保存JWT令牌，用户登录成功

## 7. 货币交易流程

### 7.1 流程描述

货币交易流程是指用户在平台上进行货币交易的流程，包括获取货币、消费货币、查看余额等操作。

```
          │                              │
```

### 7.3 详细步骤

1. **用户获取货币**：用户通过签到、比赛奖励等方式获取货币
2. **系统更新用户余额**：系统更新用户的货币余额
3. **用户查看余额**：用户可以随时查看自己的货币余额
4. **用户发起消费请求**：用户在平台上发起消费请求，如购买商品、报名付费赛事等
5. **系统检查余额**：系统检查用户的货币余额是否充足
6. **余额充足**：如果余额充足，系统执行消费操作
7. **系统扣除余额**：系统从用户余额中扣除相应的货币
8. **生成交易记录**：系统生成交易记录，记录交易详情
9. **返回消费结果**：系统返回消费结果，告知用户消费成功
10. **余额不足**：如果余额不足，系统拒绝消费请求
11. **返回错误信息**：系统返回错误信息，告知用户余额不足

## 8. 缓存更新流程

### 8.1 流程描述

缓存更新流程是指系统更新缓存数据的流程，包括缓存预热、缓存更新、缓存失效等操作。

### 8.2 流程图

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  系统启动        │────▶│  执行缓存预热     │────▶│  加载热点数据     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  数据发生变化     │────▶│  触发缓存更新事件  │────▶│  更新缓存数据     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  缓存过期        │────▶│  缓存失效        │────▶│  从数据库加载数据   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
┌─────────────────┐     ┌─────────────────┐
│  更新缓存        │────▶│  返回最新数据     │
└─────────────────┘     └─────────────────┘
```

### 8.3 详细步骤

1. **系统启动**：系统启动时，执行缓存预热
2. **执行缓存预热**：系统执行缓存预热，加载热点数据到缓存
3. **加载热点数据**：系统从数据库加载热点数据，如用户信息、赛事信息等
4. **数据发生变化**：当数据库中的数据发生变化时，触发缓存更新事件
5. **触发缓存更新事件**：系统触发缓存更新事件
6. **更新缓存数据**：系统更新缓存中的数据，确保数据一致性
7. **缓存过期**：当缓存数据过期时，缓存失效
8. **缓存失效**：缓存数据失效，需要从数据库重新加载
9. **从数据库加载数据**：系统从数据库加载最新数据
10. **更新缓存**：系统将最新数据更新到缓存
11. **返回最新数据**：系统返回最新数据给请求方
