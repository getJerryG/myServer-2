# 系统架构

## 1. 系统概述

狼人杀赛事平台后端是一个基于 Node.js + Express + TypeScript 的 Web 应用，采用分层架构设计，主要用于管理狼人杀赛事、用户、战队、货币系统等核心功能。

## 2. 架构原则

- **分层设计**：清晰的分层架构，便于维护和扩展
- **模块化**：按功能模块划分，降低耦合度
- **可扩展性**：支持横向扩展，应对高并发
- **安全性**：完善的认证和授权机制
- **性能优化**：多级缓存策略，优化数据库查询
- **实时通信**：支持 Socket.io 实时消息推送

### 3.2 各层职责

#### 3.2.1 路由层 (routes)
- **职责**：处理 HTTP 请求路由，将请求转发到对应的控制器
- **核心文件**：`src/routes/*.ts`
- **主要功能**：
  - 定义 API 端点
  - 应用中间件
  - 路由分组管理

#### 3.2.2 控制器层 (controllers)
- **职责**：处理请求逻辑，调用服务层完成业务操作
- **核心文件**：`src/controllers/*.ts`
- **主要功能**：
  - 请求参数验证
  - 调用服务层方法
  - 构建响应
  - 错误处理

#### 3.2.3 服务层 (services)
- **职责**：实现核心业务逻辑
- **核心文件**：`src/models/*/services/*.ts`
- **主要功能**：
  - 业务逻辑实现
  - 调用数据访问层
  - 缓存管理
  - 事务处理

#### 3.2.4 数据访问层 (data)
- **职责**：封装数据库操作
- **核心文件**：`src/models/*/data/*.ts`
- **主要功能**：
  - 数据库 CRUD 操作
  - 查询优化
  - 数据转换

#### 3.2.5 数据库层 (models)
- **职责**：定义数据模型和关系
- **核心文件**：`src/models/*/models/*.ts`
- **主要功能**：
  - 定义 Schema
  - 索引管理
  - 钩子函数

### 4.2 核心组件说明

#### 4.2.1 Express 应用
- **功能**：Web 服务器核心，处理 HTTP 请求
- **配置**：CORS、body-parser、中间件注册
- **入口**：`src/api.ts`

#### 4.2.2 Socket.io 服务
- **功能**：实时通信，支持消息推送
- **用途**：赛事实时通知、聊天功能、状态更新

#### 4.2.3 Redis 缓存
- **功能**：多级缓存策略，优化性能
- **用途**：用户信息缓存、热点数据缓存、会话管理

#### 4.2.4 认证中间件
- **功能**：JWT 认证和授权
- **用途**：保护 API 端点，验证用户身份

#### 4.2.5 定时任务
- **功能**：自动执行定时任务
- **用途**：赛事状态更新、缓存预热、统计计算

#### 4.2.6 中间件层
- **功能**：请求处理管道
- **主要中间件**：
  - 认证中间件
  - 角色验证中间件
  - 日志中间件
  - 错误处理中间件

## 5. 数据流与交互流程

### 5.1 典型请求流程

```
1. 客户端发送 HTTP 请求
2. Express 应用接收请求
3. 应用中间件（CORS、body-parser 等）
4. 路由层根据 URL 匹配到对应的控制器
5. 控制器验证请求参数
6. 控制器调用服务层方法
7. 服务层检查缓存
   - 命中缓存：直接返回结果
   - 未命中缓存：调用数据访问层
8. 数据访问层查询数据库
9. 数据库返回结果
10. 服务层更新缓存
11. 服务层返回结果给控制器
12. 控制器构建响应
13. 响应返回给客户端
```

### 5.2 实时通信流程

```
1. 客户端连接到 Socket.io 服务
2. 服务端进行认证
3. 客户端订阅特定房间或事件
4. 服务端发布事件到对应房间
5. 客户端接收事件并处理
```

## 8. 关键技术实现

### 8.1 认证与授权
- **JWT 认证**：无状态认证，支持跨服务调用
- **中间件验证**：全局认证中间件 + 角色验证中间件
- **权限细粒度控制**：基于角色和权限的访问控制

### 8.2 缓存策略
- **多级缓存**：本地缓存 + Redis 分布式缓存
- **缓存预热**：系统启动时加载热点数据
- **缓存更新**：主动更新 + 过期失效
- **缓存穿透防护**：布隆过滤器

### 8.3 性能优化
- **数据库索引优化**：合理设计索引
- **查询优化**：避免 N+1 查询
- **异步处理**：非阻塞 I/O
- **负载均衡**：支持多实例部署

### 8.4 安全措施
- **输入验证**：Zod 输入验证
- **密码加密**：bcryptjs 加密存储
- **CORS 配置**：安全的跨域策略
- **速率限制**：防止 API 滥用
