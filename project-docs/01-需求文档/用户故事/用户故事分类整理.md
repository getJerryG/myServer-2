# 用户故事分类整理

## 一、分类说明

### 分类维度
1. **第一层：用户维度**（功能模块）
   - 按照平台的核心功能模块进行分类，反映用户在平台上的主要活动领域
   - 每个模块包含与该功能相关的所有用户故事

2. **第二层：用户身份维度**
   - 按照用户在平台中的角色和权限进行分类
   - 每个身份包含该角色特有的用户故事

### 分类体系
| 功能模块 | 用户身份 | 包含用户故事 |
|---------|---------|-------------|
| 用户模块 | 普通用户 | US-001, US-002, US-003 |
| 战队模块 | 战队队长 | US-004, US-006 |
| 战队模块 | 战队管理员 | US-007, US-008 |
| 战队模块 | 普通用户 | US-005 |
| 赛事模块 | 赛事创建者 | US-009 |
| 赛事模块 | 赛事管理员 | US-010, US-011, US-012, US-013 |
| 系统管理模块 | 平台管理员 | US-014, US-015, US-016 |

## 二、详细分类

### 1. 用户模块

#### 1.1 普通用户

##### US-001: 微信登录
**作为** 普通用户
**我想要** 通过微信登录平台
**以便于** 快速访问平台功能，无需注册

**验收标准**：
- **场景1**: 成功登录
  - Given: 用户已安装微信并登录
  - When: 用户点击微信登录按钮
  - Then: 系统应调用微信登录API，获取用户信息，并自动登录到平台
  - Then: 用户应能看到自己的头像和昵称
  - Then: 用户应能访问平台的所有功能

- **场景2**: 登录失败
  - Given: 用户未安装微信或未登录微信
  - When: 用户点击微信登录按钮
  - Then: 系统应显示友好的错误提示，引导用户安装或登录微信
  - Then: 用户应无法登录到平台

- **场景3**: 已登录状态
  - Given: 用户已成功登录
  - When: 用户再次打开小程序
  - Then: 系统应自动识别用户已登录状态
  - Then: 用户应直接进入平台主页，无需再次登录

##### US-002: 查看赛事列表
**作为** 普通用户
**我想要** 查看平台上的赛事列表
**以便于** 找到感兴趣的赛事

**验收标准**：
- **场景1**: 查看所有赛事
  - Given: 用户已成功登录平台
  - When: 用户进入赛事列表页面
  - Then: 系统应显示所有赛事的列表
  - Then: 每个赛事应显示赛事名称、类型、状态、开始时间和报名截止时间
  - Then: 赛事应按开始时间倒序排列

- **场景2**: 筛选赛事
  - Given: 用户已成功登录平台
  - When: 用户选择筛选条件（如赛事状态、类型、难度等）
  - Then: 系统应根据筛选条件显示匹配的赛事
  - Then: 筛选结果应实时更新
  - Then: 系统应显示当前筛选条件

- **场景3**: 搜索赛事
  - Given: 用户已成功登录平台
  - When: 用户在搜索框中输入赛事名称或关键词
  - Then: 系统应显示名称或关键词匹配的赛事
  - Then: 搜索结果应实时更新
  - Then: 搜索结果应高亮显示匹配的关键词
  - Then: 当搜索框为空时，应显示所有赛事

##### US-003: 报名赛事
**作为** 普通用户
**我想要** 报名参加感兴趣的赛事
**以便于** 获得参赛资格

**验收标准**：
- **场景1**: 成功报名
  - Given: 赛事处于报名中状态，且报名人数未达上限
  - When: 用户点击报名按钮
  - Then: 系统应显示报名确认页面，包含赛事信息和报名费（如有）
  - When: 用户确认报名
  - Then: 系统应处理报名请求，扣除报名费（如有）
  - Then: 系统应显示报名成功提示
  - Then: 用户的赛事列表中应显示该赛事

- **场景2**: 报名失败（赛事已结束）
  - Given: 赛事已结束或已取消
  - When: 用户点击报名按钮
  - Then: 系统应显示友好的错误提示，说明赛事已结束或已取消
  - Then: 用户应无法完成报名

- **场景3**: 报名失败（人数已满）
  - Given: 赛事报名人数已达上限
  - When: 用户点击报名按钮
  - Then: 系统应显示友好的错误提示，说明赛事人数已满
  - Then: 用户应无法完成报名

- **场景4**: 重复报名
  - Given: 用户已成功报名该赛事
  - When: 用户再次点击报名按钮
  - Then: 系统应显示友好的提示，说明用户已报名该赛事
  - Then: 用户应无法重复报名

### 2. 战队模块

#### 2.1 战队队长

##### US-004: 创建战队
**作为** 战队队长
**我想要** 创建自己的战队
**以便于** 组织队伍参加赛事

**验收标准**：
- **场景1**: 成功创建战队
  - Given: 用户已成功登录平台
  - When: 用户进入创建战队页面，填写战队名称、战队宣言等信息
  - When: 用户点击创建按钮
  - Then: 系统应验证战队名称的唯一性
  - Then: 系统应创建战队，并将用户设置为战队队长
  - Then: 系统应显示创建成功提示
  - Then: 用户应能看到自己创建的战队

- **场景2**: 创建失败（名称重复）
  - Given: 平台上已存在同名战队
  - When: 用户使用该名称创建战队
  - Then: 系统应显示友好的错误提示，说明战队名称已存在
  - Then: 用户应无法创建战队

- **场景3**: 创建失败（信息不完整）
  - Given: 用户未填写必要信息（如战队名称）
  - When: 用户点击创建按钮
  - Then: 系统应显示友好的错误提示，指出缺少的必要信息
  - Then: 用户应无法创建战队

- **场景4**: 已有战队
  - Given: 用户已创建或加入了其他战队
  - When: 用户尝试再次创建战队
  - Then: 系统应显示友好的错误提示，说明用户已有战队
  - Then: 用户应无法创建新战队

##### US-006: 战队报名赛事
**作为** 战队队长
**我想要** 代表战队报名参加赛事
**以便于** 组织队伍参赛

**验收标准**：
- **场景1**: 成功报名
  - Given: 赛事支持战队报名，且战队人数符合赛事要求
  - When: 战队队长进入赛事详情页面，点击战队报名按钮
  - When: 战队队长确认报名信息和参赛成员
  - When: 战队队长点击确认报名
  - Then: 系统应验证战队是否符合报名条件
  - Then: 系统应处理报名请求，扣除报名费（如有）
  - Then: 系统应显示报名成功提示
  - Then: 战队的赛事列表中应显示该赛事

- **场景2**: 报名失败（赛事不支持战队报名）
  - Given: 赛事仅支持个人报名
  - When: 战队队长尝试以战队名义报名
  - Then: 系统应显示友好的错误提示，说明赛事不支持战队报名
  - Then: 战队队长应无法以战队名义报名
  - Then: 系统应提示战队队长可以以个人身份报名

- **场景3**: 报名失败（战队人数不足）
  - Given: 赛事要求战队人数至少为5人，但战队当前只有3人
  - When: 战队队长尝试报名该赛事
  - Then: 系统应显示友好的错误提示，说明战队人数不足
  - Then: 战队队长应无法完成报名
  - Then: 系统应提示战队队长还需要招募多少成员

- **场景4**: 已报名赛事
  - Given: 战队已成功报名该赛事
  - When: 战队队长再次尝试报名
  - Then: 系统应显示友好的提示，说明战队已报名该赛事
  - Then: 战队队长应无法重复报名

#### 2.2 战队管理员

##### US-007: 管理战队申请
**作为** 战队管理员
**我想要** 管理用户的战队加入申请
**以便于** 协助队长管理战队

**验收标准**：
- **场景1**: 通过申请
  - Given: 战队管理员进入战队管理页面
  - When: 战队管理员查看待处理的战队加入申请
  - When: 战队管理员选择一个申请，点击通过按钮
  - Then: 系统应将该用户加入战队
  - Then: 被通过的用户应收到加入战队成功的通知
  - Then: 战队成员列表中应显示该用户
  - Then: 战队申请列表中应移除该申请

- **场景2**: 拒绝申请
  - Given: 战队管理员进入战队管理页面
  - When: 战队管理员查看待处理的战队加入申请
  - When: 战队管理员选择一个申请，点击拒绝按钮
  - When: 战队管理员输入拒绝原因（可选）
  - When: 战队管理员确认拒绝操作
  - Then: 系统应拒绝该用户的加入申请
  - Then: 被拒绝的用户应收到加入战队失败的通知，包含拒绝原因（如有）
  - Then: 战队申请列表中应移除该申请

- **场景3**: 查看申请列表
  - Given: 战队有待处理的加入申请
  - When: 战队管理员进入战队管理页面，点击查看战队申请
  - Then: 系统应显示所有待处理的战队加入申请
  - Then: 每个申请应显示申请人的头像、昵称、申请时间等信息
  - Then: 战队管理员应对每个申请进行通过或拒绝操作

- **场景4**: 申请列表为空
  - Given: 战队没有待处理的加入申请
  - When: 战队管理员进入战队管理页面，查看战队申请
  - Then: 系统应显示友好的提示，说明当前没有待处理的申请
  - Then: 战队管理员应无法进行通过或拒绝操作

##### US-008: 发布战队公告
**作为** 战队管理员
**我想要** 发布战队公告
**以便于** 向战队成员传达重要信息

**验收标准**：
- **场景1**: 成功发布公告
  - Given: 战队管理员进入战队管理页面
  - When: 战队管理员点击发布公告按钮
  - When: 战队管理员填写公告标题和内容
  - When: 战队管理员点击发布按钮
  - Then: 系统应保存该公告
  - Then: 战队成员应收到新公告通知
  - Then: 战队公告列表中应显示该公告
  - Then: 公告应显示发布时间和发布人信息

- **场景2**: 编辑公告
  - Given: 战队管理员已发布公告
  - When: 战队管理员进入战队公告列表
  - When: 战队管理员选择一个已发布的公告，点击编辑按钮
  - When: 战队管理员修改公告内容
  - When: 战队管理员点击保存按钮
  - Then: 系统应更新该公告
  - Then: 战队成员应收到公告更新通知
  - Then: 战队公告列表中应显示更新后的公告
  - Then: 公告应显示更新时间

- **场景3**: 删除公告
  - Given: 战队管理员已发布公告
  - When: 战队管理员进入战队公告列表
  - When: 战队管理员选择一个已发布的公告，点击删除按钮
  - When: 战队管理员确认删除操作
  - Then: 系统应删除该公告
  - Then: 战队公告列表中应移除该公告
  - Then: 战队成员应无法再查看该公告

- **场景4**: 公告列表管理
  - Given: 战队有多个已发布的公告
  - When: 战队管理员进入战队公告列表
  - Then: 系统应按发布时间倒序显示所有公告
  - Then: 每个公告应显示标题、发布时间、发布人和内容摘要
  - Then: 战队管理员应对每个公告进行编辑或删除操作

- **场景5**: 查看公告详情
  - Given: 战队有已发布的公告
  - When: 战队管理员或普通成员点击某个公告
  - Then: 系统应显示公告的完整内容
  - Then: 应显示公告的发布时间、发布人和更新时间（如有）

#### 2.3 普通用户

##### US-005: 管理战队成员
**作为** 普通用户
**我想要** 管理战队成员
**以便于** 控制战队成员组成

**验收标准**：
- **场景1**: 邀请成员
  - Given: 用户是战队队长
  - When: 用户进入战队管理页面，点击邀请成员按钮
  - When: 用户输入邀请码或选择平台用户
  - When: 用户发送邀请
  - Then: 系统应生成邀请码或发送邀请

- **场景2**: 移除成员
  - Given: 用户是战队队长，战队中有其他成员
  - When: 用户进入战队成员列表，选择要移除的成员
  - When: 用户点击移除按钮
  - When: 用户确认移除操作
  - Then: 系统应将该成员从战队中移除
  - Then: 被移除的成员应收到战队移除通知
  - Then: 被移除成员的战队信息应更新

- **场景3**: 设置管理员
  - Given: 用户是战队队长，战队中有其他成员
  - When: 用户进入战队成员列表，选择要设置为管理员的成员
  - When: 用户点击设为管理员按钮
  - Then: 系统应将该成员的角色从普通成员变为战队管理员
  - Then: 该成员应获得战队管理员的权限
  - Then: 战队成员列表中应显示该成员的管理员身份

- **场景4**: 取消管理员
  - Given: 用户是战队队长，战队中有战队管理员
  - When: 用户进入战队成员列表，选择要取消管理员的成员
  - When: 用户点击取消管理员按钮
  - Then: 系统应将该成员的角色从战队管理员变为普通成员
  - Then: 该成员应失去战队管理员的权限
  - Then: 战队成员列表中应更新该成员的身份

**验收标准**：

  - Then: 系统应验证赛事名称的唯一性

##### US-011: 管理赛事报名
**作为** 赛事管理员
**我想要** 管理赛事报名
**以便于** 控制参赛人员

**验收标准**：
- **场景1**: 审核报名
  - Given: 赛事有报名申请
  - When: 赛事管理员进入赛事管理页面，点击查看报名
  - When: 赛事管理员选择一个报名申请，点击审核按钮
  - When: 赛事管理员选择通过或拒绝

  - Then: 系统应更新该报名申请的状态

  - Given: 赛事有报名申请
  - When: 赛事管理员进入赛事管理页面，点击查看报名统计
  - Then: 系统应显示报名人数、男女比例等统计信息
  - Then: 系统应按状态显示报名人数分布

##### US-012: 管理赛事状态
**作为** 赛事管理员
**我想要** 管理赛事状态
**以便于** 控制赛事流程

**验收标准**：
- **场景1**: 更新赛事状态
  - Given: 赛事管理员进入赛事管理页面
  - When: 赛事管理员选择一个赛事，点击状态管理按钮
  - When: 赛事管理员选择新的状态
  - When: 赛事管理员点击确认按钮
  - Then: 系统应更新该赛事的状态
  - Then: 参赛用户应收到赛事状态变更通知
  - Then: 赛事列表中应显示更新后的赛事状态

- **场景2**: 状态转换限制
  - Given: 赛事处于已结束状态
  - When: 赛事管理员尝试将状态改为进行中
  - Then: 系统应显示友好的错误提示，说明状态转换不允许
  - Then: 赛事管理员应无法完成状态转换

##### US-013: 管理赛事结果
**作为** 赛事管理员
**我想要** 管理赛事的结果
**以便于** 公布比赛成绩

**验收标准**：
- **场景1**: 录入比赛结果
  - Given: 赛事处于进行中状态，且有已完成的比赛
  - When: 赛事管理员进入赛事管理页面
  - When: 赛事管理员选择已完成的比赛，点击录入结果按钮
  - When: 赛事管理员填写比赛结果，包括获胜方、选手得分等信息
  - When: 赛事管理员点击保存按钮
  - Then: 系统应保存该比赛的结果
  - Then: 该比赛的状态应改为已完成
  - Then: 选手的个人成绩应更新
  - Then: 赛事的总成绩排名应更新

- **场景2**: 修改比赛结果
  - Given: 赛事管理员已录入比赛结果
  - When: 赛事管理员进入赛事管理页面
  - When: 赛事管理员选择已录入结果的比赛，点击修改结果按钮
  - When: 赛事管理员修改比赛结果
  - When: 赛事管理员点击保存按钮
  - Then: 系统应更新该比赛的结果
  - Then: 选手的个人成绩应重新计算
  - Then: 赛事的总成绩排名应重新生成
  - Then: 系统应记录结果修改日志

- **场景3**: 公布比赛结果
  - Given: 赛事管理员已录入所有比赛结果
  - When: 赛事管理员进入赛事管理页面
  - When: 赛事管理员点击公布结果按钮
  - When: 赛事管理员确认操作
  - Then: 系统应将赛事结果设置为可见状态
  - Then: 系统应向所有参赛用户发送结果公布通知
  - Then: 普通用户应能查看赛事结果
  - Then: 赛事详情页面应显示完整的比赛结果和排名

- **场景4**: 查看和导出结果数据
  - Given: 赛事已结束，且结果已公布
  - When: 赛事管理员进入赛事管理页面
  - When: 赛事管理员点击查看结果按钮
  - Then: 系统应显示完整的赛事结果，包括各轮次成绩和最终排名
  - Then: 赛事管理员应能按选手、轮次等筛选结果
  - When: 赛事管理员点击导出结果按钮
  - Then: 系统应生成并下载赛事结果数据文件
  - Then: 导出的文件应包含所有比赛结果和统计数据

- **场景5**: 错误的结果操作
  - Given: 赛事未开始或处于报名中状态
  - When: 赛事管理员尝试录入比赛结果
  - Then: 系统应显示友好的错误提示，说明赛事尚未开始或未到录入结果阶段
  - Then: 赛事管理员应无法录入结果

##### US-014: 管理赛事模板

**我想要** 管理赛事模板

  - When: 平台管理员点击保存按钮
  - Then: 系统应保存该赛事模板
  - Then: 赛事创建者应能在创建赛事时选择该模板

- **场景2**: 编辑赛事模板
  - Given: 平台管理员已创建赛事模板
  - When: 平台管理员进入系统管理页面，点击查看赛事模板
  - When: 平台管理员选择一个模板，点击编辑按钮
  - When: 平台管理员修改模板内容
  - When: 平台管理员点击保存按钮
  - Then: 系统应更新该赛事模板
  - Then: 后续创建的赛事应使用更新后的模板

- **场景3**: 删除赛事模板
  - Given: 平台管理员已创建赛事模板
  - When: 平台管理员进入系统管理页面，点击查看赛事模板
  - When: 平台管理员选择一个模板，点击删除按钮
  - When: 平台管理员确认删除操作
  - Then: 系统应删除该赛事模板
  - Then: 赛事创建者应无法再选择该模板

- **场景4**: 查看模板列表
  - Given: 系统中有多个赛事模板
  - When: 平台管理员进入系统管理页面，点击查看赛事模板
  - Then: 系统应显示所有赛事模板
  - Then: 每个模板应显示名称、创建时间、更新时间等信息
  - Then: 平台管理员应对每个模板进行编辑或删除操作

##### US-015: 管理用户
**作为** 平台管理员
**我想要** 管理平台用户
**以便于** 维护平台秩序，处理违规用户

**验收标准**：
- **场景1**: 查看用户列表
  - Given: 平台管理员已登录系统
  - When: 平台管理员进入系统管理页面，点击查看用户列表
  - Then: 系统应显示所有平台用户
  - Then: 每个用户应显示基本信息，包括头像、昵称、用户ID、注册时间、最后登录时间等
  - Then: 平台管理员应能根据用户角色、注册时间等条件筛选用户
  - Then: 平台管理员应能搜索特定用户

- **场景2**: 查看用户详情
  - Given: 系统中有注册用户
  - When: 平台管理员进入用户列表，选择一个用户，点击查看详情按钮
  - Then: 系统应显示该用户的详细信息，包括用户基本信息、战队信息、赛事参与记录、违规记录等
  - Then: 平台管理员应能查看用户的完整活动日志

- **场景3**: 禁用用户
  - Given: 平台管理员已登录系统
  - When: 平台管理员进入用户列表，选择一个违规用户，点击禁用按钮
  - When: 平台管理员输入禁用原因和禁用时长
  - When: 平台管理员确认操作
  - Then: 系统应将该用户状态改为禁用
  - Then: 该用户应无法登录平台
  - Then: 系统应向该用户发送禁用通知，包含禁用原因和时长
  - Then: 该用户的禁用状态应在禁用时长结束后自动恢复

- **场景4**: 解除用户禁用
  - Given: 系统中有被禁用的用户
  - When: 平台管理员进入用户列表，选择一个被禁用的用户，点击解除禁用按钮
  - When: 平台管理员确认操作
  - Then: 系统应将该用户状态改为正常
  - Then: 该用户应能重新登录平台
  - Then: 系统应向该用户发送解除禁用通知

- **场景5**: 删除用户
  - Given: 平台管理员已登录系统，且有确定需要删除的用户
  - When: 平台管理员进入用户列表，选择一个用户，点击删除按钮
  - When: 平台管理员确认删除操作
  - Then: 系统应永久删除该用户的所有数据
  - Then: 该用户应无法再登录平台
  - Then: 系统应记录用户删除日志
