# 需求说明

## 1. 项目概述

狼人杀赛事平台后端是一个基于 Node.js + Express + TypeScript 的 Web 应用，用于支持狼人杀赛事的创建、管理、报名和执行等全流程。系统采用分层架构设计，支持高并发、实时通信和多级缓存，确保赛事的顺利进行和用户的良好体验。

### 1.1 项目目标

- 提供完整的狼人杀赛事管理功能
- 支持多种赛制和版型
- 实现实时赛事通知和状态更新
- 提供完善的用户管理和认证机制
- 支持赛事数据统计和分析
- 确保系统的高可用性和性能

### 1.2 项目范围

- 后端服务开发
- 数据库设计和实现
- API 接口设计和文档
- 实时通信功能
- 缓存策略设计
- 安全认证机制

## 2. 核心功能模块

### 2.1 用户管理模块

#### 2.1.1 功能描述

- **用户注册与登录**：支持微信 OpenID 登录
- **用户信息管理**：用户基本信息的查询和更新
- **用户角色管理**：区分普通用户、赛事管理员和系统管理员
- **用户权限控制**：基于角色的权限管理
- **用户签到**：每日签到功能

#### 2.1.2 业务规则

- 用户必须通过微信登录才能使用系统
- 不同角色拥有不同的操作权限
- 用户签到可以获得相应的奖励

### 2.2 赛事管理模块

#### 2.2.1 功能描述

- **赛事创建**：创建新的狼人杀赛事
- **赛事编辑**：修改赛事信息
- **赛事状态管理**：管理赛事的各个阶段（未开始、报名中、进行中、已结束、已取消、已删除）
- **赛事查询**：根据条件查询赛事
- **赛事统计**：统计赛事数据

#### 2.2.2 业务规则

- 赛事名称必须唯一
- 赛事必须设置开始时间和结束时间
- 赛事状态转换必须符合流程
- 赛事创建者拥有赛事的管理权限

### 2.3 赛程管理模块

#### 2.3.1 功能描述

- **赛程创建**：为赛事创建赛程
- **赛程编辑**：修改赛程信息
- **轮次管理**：管理赛事的各个轮次
- **比赛安排**：安排具体的比赛
- **比赛状态管理**：管理比赛的状态（已安排、进行中、已完成、已取消）
- **版型管理**：管理比赛的版型

#### 2.3.2 业务规则

- 赛程必须关联到具体的赛事
- 比赛必须设置时间、地点和版型
- 比赛版型必须在当天开放
- 比赛状态转换必须符合流程

### 2.4 报名管理模块

#### 2.4.1 功能描述

- **赛事报名**：用户或队伍报名参加赛事
- **报名审核**：审核用户或队伍的报名
- **报名查询**：查询报名信息
- **报名统计**：统计报名数据

#### 2.4.2 业务规则

- 报名必须在赛事的报名时间内进行
- 报名人数或队伍数不能超过赛事限制
- 付费赛事需要完成支付才能报名成功

### 2.5 群组管理模块

#### 2.5.1 功能描述

- **群组创建**：创建新的群组
- **群组管理**：管理群组信息和成员
- **群组权限控制**：管理群组的权限
- **群组活动**：组织群组内的活动

#### 2.5.2 业务规则

- 群组名称必须唯一
- 群组创建者拥有群组的管理权限
- 群组可以关联到特定的赛事

### 2.6 货币系统模块

#### 2.6.1 功能描述

- **货币管理**：管理用户的货币余额
- **货币交易**：处理货币的收支
- **交易记录**：记录所有货币交易
- **奖励机制**：发放奖励和惩罚

#### 2.6.2 业务规则

- 货币交易必须记录详细信息
- 奖励和惩罚必须符合规则
- 货币余额不能为负数

### 2.7 媒体服务模块

#### 2.7.1 功能描述

- **图片上传**：上传用户头像、赛事海报等图片
- **图片处理**：调整图片大小、格式等
- **图片存储**：安全存储图片

#### 2.7.2 业务规则

- 图片大小和格式必须符合要求
- 图片必须经过处理才能使用
- 图片存储必须安全可靠

### 2.8 实时通信模块

#### 2.8.1 功能描述

- **赛事通知**：实时通知赛事状态变化
- **聊天功能**：支持用户和赛事内聊天
- **状态同步**：同步赛事和比赛的实时状态

#### 2.8.2 业务规则

- 实时消息必须可靠送达
- 聊天内容必须符合规范
- 状态同步必须及时准确

## 3. 非功能需求

### 3.1 性能需求

- **响应时间**：API 响应时间不超过 500ms
- **并发支持**：支持至少 1000 并发用户
- **吞吐量**：每秒处理至少 100 个请求
- **缓存策略**：采用多级缓存，缓存命中率不低于 80%

### 3.2 安全性需求

- **认证机制**：采用 JWT 认证
- **数据加密**：敏感数据加密存储
- **访问控制**：基于角色的访问控制
- **防止攻击**：防止 SQL 注入、XSS 等攻击
- **日志记录**：记录所有关键操作

### 3.3 可靠性需求

- **可用性**：系统可用性不低于 99.9%
- **容错机制**：具备故障恢复能力
- **数据备份**：定期备份数据
- **错误处理**：完善的错误处理机制

### 3.4 可扩展性需求

- **模块化设计**：支持功能模块的独立扩展
- **横向扩展**：支持多实例部署
- **API 版本控制**：支持 API 版本管理
- **插件机制**：支持插件扩展

### 3.5 可维护性需求

- **代码规范**：严格的代码规范
- **文档完整性**：完善的文档
- **测试覆盖率**：测试覆盖率不低于 80%
- **日志管理**：完善的日志管理

### 3.6 兼容性需求

- **浏览器兼容性**：支持主流浏览器
- **设备兼容性**：支持移动端和桌面端
- **API 兼容性**：保持 API 的向后兼容

- **构建工具**：Webpack

### 4.2 开发环境

- **包管理器**：pnpm

### 4.3 部署环境

- **容器化**：支持 Docker 部署
- **CI/CD**：支持 CI/CD 流程
