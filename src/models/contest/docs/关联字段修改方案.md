# 关联字段修改方案

## 1. 问题分析

当前竞赛系统中存在关联字段设计不一致的问题：
- 部分模型使用自增数字ID (`contestId`) 作为关联字段
- 部分模型使用字符串ID (`contestId`) 作为关联字段
- 字段命名不直观，未明确表示关联关系
- 未充分利用MongoDB自动生成的ObjectId

## 2. 修改目标

- 统一关联字段命名规范
- 统一关联字段类型为MongoDB ObjectId
- 符合MongoDB最佳实践
- 保持业务ID的可用性

## 3. 修改方案

### 3.1 命名规范

| 当前命名 | 建议命名 | 说明 |
|----------|----------|------|
| `contestId` | `contest_id` | 关联字段使用下划线命名法 |
| `scheduleId` | `schedule_id` | 关联字段使用下划线命名法 |
| `registrationId` | `registration_id` | 关联字段使用下划线命名法 |
| `matchId` | `match_id` | 关联字段使用下划线命名法 |

### 3.2 类型规范

| 字段类型 | 适用场景 |
|----------|----------|
| `ObjectId` | 所有关联字段 |
| `Number` | 业务ID（如`contestId`，用于用户展示） |
| `String` | 普通字符串字段 |
