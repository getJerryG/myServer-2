# 狼人杀小程序服务端项目规则

## 1. 项目概述
本项目是基于 Node.js + TypeScript + Mongoose + Socket.IO + Redis 的狼人杀小程序服务端，用于管理玩家数据、房间、聊天、游戏流程等功能。

## 2. 目录结构规范

### 2.1 核心目录
```
├── src/                    # 源代码目录
├── .#md/                   # 文档类文件存储
├── text/                   # 测试类文件存储
├── types/                  # 类型定义
├── config/                 # Webpack配置
├── dist/                   # 编译输出目录
├── public/                 # 静态资源
├── uploads/                # 上传文件存储
└── .env                    # 环境变量配置
```

### 2.2 文档文件存放规则
- **所有文档类文件必须统一存放在 `.#md/` 目录下**
- 包括但不限于：技术文档、API接口文档、数据库设计文档、部署文档、开发计划、重构计划、技术方案文档等
- 文档格式统一使用 Markdown 格式
- 文档命名清晰，使用中文或英文描述文档内容

### 2.3 测试文件存放规则
- **所有测试类文件必须统一存放在 `src/test/` 目录下**
- 包括：单元测试、集成测试、端到端测试等
- 测试文件命名格式：`被测试模块名.test.ts`
- 测试目录结构与 `src/` 保持一致，便于定位和维护
- 测试覆盖率要求不低于 80%

## 3. 代码规范

### 3.1 TypeScript 配置
- 严格遵循项目 `tsconfig.json` 配置
- 启用 `noUnusedLocals` 和 `noUnusedParameters` 检测
- 使用路径别名：`@/*` 指向 `src/`，`~/*` 指向 `types/`

### 3.2 代码格式
- 4 个空格缩进
- 每行代码长度不超过 120 字符
- 操作符前后添加空格
- 大括号 `{` 与语句同行，`}` 单独一行
- 控制语句大括号不可省略

### 3.3 命名约定
- 文件名/目录名：小驼峰命名法（如 `userService.ts`）
- 变量名：小驼峰命名法（如 `userName`）
- 常量：全大写字母，下划线分隔（如 `MAX_USER_COUNT`）
- 布尔类型：`is` 或 `has` 前缀（如 `isLogin`）
- 类名：大驼峰命名法（如 `UserService`）
- 函数名：小驼峰命名法（如 `getUserInfo`）
- 私有方法：下划线前缀（如 `_privateMethod`）

## 4. 提交信息规范

### 4.1 提交格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

### 4.2 Type 类型
- `feat`：新功能
- `fix`：修复 bug
- `docs`：文档更新
- `style`：代码格式调整
- `refactor`：代码重构
- `perf`：性能优化
- `test`：测试相关
- `build`：构建配置更新
- `chore`：其他杂项

### 4.3 示例
```
feat(user): 添加用户登录功能

- 实现 JWT 认证
- 添加密码加密
- 增加登录日志

Closes #123
```

## 5. 分支管理

### 5.1 分支类型
- `master`：生产环境分支
- `develop`：开发环境分支
- `feature/*`：新功能开发分支
- `bugfix/*`：bug 修复分支
- `hotfix/*`：紧急修复分支

### 5.2 分支流程
1. 从 `develop` 创建 `feature/*` 或 `bugfix/*` 分支
2. 开发完成后提交 PR 到 `develop`
3. 测试通过后合并到 `develop`
4. 发布时从 `develop` 创建 `release/*` 分支，测试后合并到 `master` 和 `develop`

## 6. 安全要求

### 6.1 数据安全
- 密码使用 bcrypt 哈希存储
- 敏感数据存储在环境变量中
- 禁止硬编码敏感信息

### 6.2 API 安全
- 所有 API 接口必须参数验证
- 实现请求频率限制
- 防止 SQL 注入、XSS 攻击

## 7. 错误处理

### 7.1 错误类型
- 定义统一错误码
- 区分业务错误和系统错误
- 错误信息使用中文

### 7.2 错误日志
- 所有错误必须记录日志
- 日志包含错误类型、信息、堆栈跟踪、请求信息

## 8. 开发环境配置

### 8.1 环境变量
- 使用 `.env` 文件管理环境变量


### 8.2 开发工具
- Node.js 版本：16.x 或以上
- 使用 pnpm 作为包管理器
- 开发命令：`pnpm run dev`
- 构建命令：`pnpm run build`

## 9. 附则

- 本规则将根据项目发展和团队反馈定期更新
- 所有团队成员必须严格遵守本规则
- 代码提交前必须确保所有测试通过
- 代码必须经过代码审查才能合并到主分支

---

本规则旨在确保项目代码的一致性、可维护性和可扩展性，提高团队协作效率，保障项目质量。
