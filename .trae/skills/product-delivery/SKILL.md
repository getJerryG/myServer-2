# 产品交付管理技能

## 功能介绍

该技能通过以下核心功能帮助团队高效管理产品交付流程：
1. **需求确认与追踪**：记录和追踪产品需求，确保所有需求都得到明确和实现
2. **开发进度管理**：跟踪开发任务的进度，识别潜在的延期风险
3. **测试验证管理**：管理测试用例、测试结果和缺陷跟踪
4. **功能完整性检查**：全面验证产品功能的完整性和可用性，确保所有功能按预期工作
5. **用户角度风险评估**：从最终用户视角评估产品使用风险，确保产品质量和用户体验
6. **交付文档生成**：自动生成标准化的产品交付文档
7. **交付验收管理**：协助进行产品交付验收和签署流程，包括预验收、正式验收、问题整改和最终签署环节
8. **交付审查报告**：根据通用产品交付审查清单生成全面的审查报告

## 使用场景

当团队需要以下功能时，应调用此技能：
1. **产品交付准备**：准备产品交付所需的各项文档和资源
2. **开发进度监控**：实时监控项目开发进度，确保按时交付
3. **测试流程管理**：管理测试用例、执行测试和跟踪缺陷
4. **交付文档生成**：生成标准化的产品交付文档
5. **验收流程管理**：协助进行产品验收和签署

## 核心特性
1. 需求管理
   - 需求基线固化与版本控制
   - 需求 - 代码映射校验，消除功能冗余
   - 需求变更影响评估与追踪
2.  进度管理
   -  开发任务进度跟踪与里程碑提醒
   -  代码质量自动扫描（变量冗余、无用函数检测）
   -  风险识别与分级预警（延期 / 质量风险）
3. 测试管理
   -  多维度测试数据整合（单元测试、类型检查、手动测试）
   -  缺陷分级管理（阻断级 / 严重级 / 一般级）与修复验证
   -  测试覆盖度统计与达标校验
4. 功能完整性检查
   -  核心功能完整性验证：确保所有需求中定义的功能都已实现
   -  功能关联性校验：验证功能之间的交互是否正常，无冲突
   -  边界场景测试：验证极端条件下功能的稳定性
   -  回归测试覆盖率验证：确保新功能不影响已有功能
5. 用户角度风险评估
   -  用户体验风险评估：评估产品的易用性、响应速度和稳定性
   -  业务场景风险评估：验证核心业务流程的完整性和正确性
   -  数据安全风险评估：确保用户数据的安全性和隐私保护
   -  生产环境适配性评估：验证产品在生产环境中的兼容性和稳定性
6. 文档生成
   -  自动生成标准化交付文档（支持自定义模板）
   -  技术栈专项内容补充（如 Node.js/TypeScript 依赖、部署配置）
   -  敏感信息脱敏（避免密钥 / 密码明文暴露）
   -  文档版本控制与评审流程管理
7. 验收管理
   -  验收标准量化核验（需求实现率、问题闭环率）
   -  已知问题风险评估与记录
   -  交付物归档与可追溯管理
   
## 使用示例

### 示例1：生成产品交付文档

```
product-delivery
```

**执行流程**：
在.trae/output/生成以下所需文档内容
1. 需求实现状态采集与校验
   1.1 拉取项目需求基线：读取需求说明.md和用户故事分类整理.md，提取所有需求 ID、描述、优先级。
   1.2 执行需求 - 代码映射校验：核对代码仓库中各功能模块（如用户管理、赛事管理）的实现代码，标记每个需求 ID 对应的开发分支、负责人、是否合并主分支。
   1.3 排查功能冗余：对比需求基线，识别代码中存在但需求未提及的功能，记录冗余功能的用途、代码路径及处理建议。
   1.4 输出《需求实现状态明细表》，字段包含：需求 ID、需求描述、对应模块、开发状态、冗余标记、备注。
   1.5 质量卡点：需求实现率需≥95%，功能冗余率需 < 5%，否则暂停流程并提示优化。
2. 测试结果数据整合与问题闭环
   2.1 收集多维度测试数据：
   自动化测试：获取 Jest 单元测试 / 接口测试报告，统计用例数、通过数、失败数、通过率；
   类型检查：运行pnpm run typecheck，导出 TypeScript 类型错误清单，按阻断级 / 警告级分级；
   手动测试：整理测试人员提交的缺陷清单，记录缺陷等级、复现步骤、当前状态。
   2.2 执行问题修复验证：针对标记为「已修复」的缺陷 / 类型错误，重新运行对应测试 / 类型检查，确认问题闭环。
   2.3 未修复问题风险评估：对未修复的非阻断级问题，标注影响范围、优先级、计划修复时间，形成《测试问题风险评估表》。
   2.4 质量卡点：阻断级问题必须 100% 修复，核心模块测试覆盖度需≥80%，否则暂停流程。
3. 功能完整性检查
   3.1 核心功能完整性验证：遍历所有需求中的功能点，逐一验证代码实现情况，形成《功能完整性验证报告》
   3.2 功能关联性校验：测试功能之间的交互场景，验证数据流转和状态同步是否正常
   3.3 边界场景测试：模拟极端条件下的功能使用，如大量数据、高频操作、异常输入等
   3.4 回归测试覆盖率验证：确保新功能未破坏已有功能，回归测试覆盖率需≥90%
   3.5 输出《功能完整性检查报告》，字段包含：功能点 ID、功能描述、验证结果、问题记录、修复建议
   3.6 质量卡点：功能完整性需≥98%，核心功能需100%通过，否则暂停流程并提示优化
4. 用户角度风险评估
   4.1 用户体验风险评估：评估产品的易用性、响应速度、稳定性，模拟真实用户操作场景
   4.2 业务场景风险评估：验证核心业务流程的完整性和正确性，确保业务逻辑无漏洞
   4.3 数据安全风险评估：检查用户数据的安全性、隐私保护措施、数据备份策略
   4.4 生产环境适配性评估：验证产品在生产环境中的兼容性、性能表现和资源占用
   4.5 输出《用户角度风险评估报告》，字段包含：风险类型、风险描述、影响范围、风险等级、缓解措施
   4.6 质量卡点：高风险问题必须100%解决，中风险问题需≤2个，否则暂停流程
5. 交付到生产环境准备
   5.1 生产环境配置检查：验证生产环境的硬件、软件、网络配置是否符合要求
   5.2 部署脚本验证：测试部署脚本的完整性和正确性，确保能够顺利部署
   5.3 回滚方案验证：测试回滚脚本和流程，确保在出现问题时能够快速回滚
   5.4 监控方案配置：确保生产环境的监控系统能够正常运行，覆盖关键指标
   5.5 输出《生产环境部署准备报告》，字段包含：配置项、检查结果、问题记录、解决方案
6. 交付文档数据校验
   6.1 一致性校验：核对《需求实现状态明细表》、《功能完整性检查报告》、《用户角度风险评估报告》与测试数据
   6.2 敏感信息校验：检查部署配置、数据库连接等内容，确保 JWT 密钥、数据库密码等敏感信息未明文写入文档
   6.3 技术栈适配性校验：针对 Node.js/TypeScript 项目，确认依赖清单、构建命令、部署配置与项目实际一致
7. 标准化交付文档生成
7.1 基于预设模板填充核心内容：
   -  项目概述（名称、版本、交付日期、交付对象）；
   -  需求实现情况（引用步骤 1.4 的明细表）；
   -  功能完整性检查结果（引用步骤 3.5 的报告）；
   -  用户角度风险评估结果（引用步骤 4.5 的报告）；
   -  测试结果（测试类型、用例数、通过率、问题统计）；
   -  生产环境部署准备情况（引用步骤 5.5 的报告）；
   -  部署说明（环境要求、构建步骤、启动命令、配置项说明）；
   -  已知问题与风险（引用步骤 2.3 的风险评估表）；
   -  联系人与维护信息。
7.2 补充技术栈专项内容（Node.js/TypeScript 项目）：
   -  核心依赖清单（package.json关键依赖及版本）；
   -  TypeScript 类型检查报告摘要；
   -  PM2/Docker 部署配置示例；
   -  常见问题排查步骤。
7.3 生成文档初稿（支持 Markdown/PDF 格式）。
8. 文档评审与版本归档
   8.1 发起评审流程：将文档初稿同步给开发、测试、产品负责人，明确评审截止时间与反馈方式。
   8.2 意见整合与文档修订：根据评审意见修改文档，解决内容遗漏、数据错误等问题。
   8.3 版本标记与归档：生成最终版文档，标记版本号（如V1.0.0），归档到项目指定目录（如project-docs/05-交付文档）。

## 注意事项

1. **数据准确性**：请确保提供的需求、进度和测试数据准确无误
2. **权限管理**：
   - 产品交付涉及敏感信息，请确保只有授权人员可以访问
   - 建议使用以下权限矩阵：
     | 角色 | 需求管理 | 进度查看 | 测试管理 | 文档生成 | 验收管理 |
     |------|----------|----------|----------|----------|----------|
     | 产品经理 | 全部权限 | 全部权限 | 查看权限 | 编辑权限 | 编辑权限 |
     | 开发人员 | 查看权限 | 编辑权限 | 查看权限 | 查看权限 | 查看权限 |
     | 测试人员 | 查看权限 | 查看权限 | 编辑权限 | 查看权限 | 查看权限 |
     | 客户 | 查看权限 | 查看权限 | 查看权限 | 查看权限 | 编辑权限 |
     | 管理员 | 全部权限 | 全部权限 | 全部权限 | 全部权限 | 全部权限 |
3. **文档模板**：可以根据组织需求自定义交付文档模板
4. **流程定制**：
   - 支持根据不同项目的交付流程进行定制
   - 定制化配置示例：
     - **敏捷项目**：简化需求文档，增加迭代计划和回顾环节
     - **瀑布项目**：完整的需求规格说明书，严格的阶段评审
     - **增量交付**：区分基础版本和迭代版本的交付内容
5. **实时更新**：建议定期更新进度和测试数据，确保信息的及时性
6. **风险预警**：当识别到潜在风险时，会及时发出预警通知
7. **验收标准**：建议在项目初期明确验收标准，确保交付质量
8. **自动化集成**：
   - 支持与Jira集成，自动同步任务进度
   - 支持与Jenkins集成，自动触发构建部署
   - 支持与Git集成，自动获取版本信息
   - 支持与Confluence集成，自动生成文档

## 项目评级标准

### 评级等级定义
| 评级 | 描述 | 交付状态 |
|------|------|----------|
| A+ | 优秀 | 完全符合交付标准，无任何问题 |
| A  | 良好 | 基本符合交付标准，仅有少量轻微问题 |
| B  | 合格 | 符合交付标准，存在一些需要改进的问题 |
| C  | 待改进 | 基本符合交付标准，但存在较多需要改进的问题 |
| D  | 不合格 | 不符合交付标准，存在严重问题 |
| E  | 不可交付 | 严重不符合交付标准，无法交付 |

### 评级依据
| 审查维度 | 权重 | 评分标准 |
|----------|------|----------|
| 代码相关审查 | 40% | 包括代码质量与规范、逻辑与模块化、安全合规 |
| 性能相关审查 | 20% | 包括系统性能、资源与缓存、稳定性与并发 |
| 注释相关审查 | 10% | 包括注释规范、注释时效性与冗余控制 |
| 文档相关审查 | 20% | 包括各类文档的完整性与质量 |
| 交付前最终校验 | 10% | 包括自动化检查、全流程验证、问题闭环、归档整理 |

### 评级计算方法
1. 每个审查项按照 ✅ 通过（1分）、⏳ 部分通过（0.5分）、❌ 失败（0分）评分
2. 各维度得分 = 维度内审查项平均得分 × 权重
3. 总得分 = 各维度得分之和
4. 评级对应：
   - 100分：SSS
   - 95-100分：S
   - 90-95分：A+
   - 80-89分：A
   - 70-79分：B
   - 60-69分：C
   - 50-59分：D
   - 0-49分：E
