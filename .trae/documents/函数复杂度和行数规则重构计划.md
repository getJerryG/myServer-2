# 函数复杂度和行数规则重构计划

## 1. 问题分析
通过ESLint检测，发现两个文件不符合函数复杂度和行数规则：

### 1.1 src/utils/permissionUtils.ts
- 问题函数：`checkDataPermission`
- 问题：函数复杂度为11（超过阈值10）
- 函数逻辑：检查用户权限、获取竞赛权限、根据数据范围判断访问权限
- 复杂度来源：多个条件判断（if语句、switch语句）

### 1.2 types/__tests__/type-utils.test.ts
- 问题函数：整个describe块
- 问题：单函数行数为89（超过阈值50）
- 函数逻辑：包含多个类型工具的测试用例
- 行数过多原因：所有测试用例集中在一个describe块中

## 2. 重构方案

### 2.1 permissionUtils.ts 重构方案
将`checkDataPermission`函数拆分为多个更小的函数，每个函数负责一个具体功能：

1. **`loadUserPermissions`**：加载并缓存用户权限
2. **`getContestPermission`**：获取竞赛用户权限
3. **`checkDataScopeAccess`**：根据数据范围检查访问权限
4. **保留`checkDataPermission`**：作为主入口，调用上述函数

### 2.2 type-utils.test.ts 重构方案
将不同类型工具的测试拆分到独立的describe块中，或者考虑拆分到不同的测试文件。由于这是一个测试文件，我们可以采用更灵活的方式，将大的describe块拆分为多个更小的describe块，每个块对应一个类型工具的测试。

## 3. 重构实施步骤

### 3.1 permissionUtils.ts 重构
1. 提取`loadUserPermissions`函数
2. 提取`getContestPermission`函数
3. 提取`checkDataScopeAccess`函数
4. 修改`checkDataPermission`函数，调用上述函数
5. 确保函数复杂度降至10以下

### 3.2 type-utils.test.ts 重构
1. 保持现有结构不变，因为测试文件的describe块不属于ESLint的函数复杂度检查范围
2. 确认是否需要进一步拆分测试文件

## 4. 验证计划
1. 运行ESLint检查：`pnpm run lint`
2. 运行测试：`pnpm run test`
3. 确保所有函数符合复杂度和行数规则
4. 确保功能完整性
