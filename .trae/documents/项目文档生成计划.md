## 3. 文档生成顺序

1. 首先生成 `技术栈.md` 和 `系统架构.md`，建立技术基础
2. 接着生成 `数据库 schema.md`，了解数据结构
3. 然后生成 `需求说明.md` 和 `用户故事.md`，明确业务需求
4. 再生成 `API契约.md` 和 `业务流程.md`，详细说明接口和业务流程
5. 最后生成 `测试策略.md`，规划测试策略

## 4. 需要提前准备的信息

1. 项目的具体业务场景和核心流程细节
2. 数据库模型的详细字段和关系
3. API接口的详细设计和参数规范
4. 业务逻辑中的关键规则和约束
5. 测试环境和测试数据的准备

## 5. 执行步骤

1. 创建 `project-docs` 文件夹及其子目录
2. 根据上述规划依次生成每个文档
3. 确保文档内容与项目代码保持一致
4. 验证文档的完整性和准确性

通过以上计划，我将生成一套完整、准确、易于维护的中文项目文档，帮助团队更好地理解和维护项目。
