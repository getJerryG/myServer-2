## 阶段二：权限验证中间件（预计 2 天）

  - 实现数据权限过滤逻辑

### 2.2 中间件增强
- **扩展认证中间件** (`src/middlewares/auth.ts`)
  - 添加权限加载逻辑（从 Redis）
  - 添加权限验证装饰器
  - 添加数据权限过滤装饰器
  - 保留现有认证逻辑

### 2.3 装饰器实现
- **创建权限装饰器** (`src/decorators/permission.ts`)
  - `@RequirePermission` - 单个权限验证
  - `@RequireAnyPermission` - 多个权限（OR）
  - `@RequireAllPermissions` - 多个权限（AND）
  - `@RequireRole` - 角色验证
  - `@RequireDataScope` - 数据权限验证

## 阶段三：权限管理接口（预计 2 天）

### 3.1 权限管理路由
- **创建权限路由** (`src/routes/permissionRoutes.ts`)
  - GET `/api/permissions` - 获取权限列表
  - POST `/api/permissions` - 创建权限
  - PUT `/api/permissions/:id` - 更新权限
  - DELETE `/api/permissions/:id` - 删除权限

### 3.2 角色管理路由
- **创建角色路由** (`src/routes/roleRoutes.ts`)
  - GET `/api/roles` - 获取角色列表
  - POST `/api/roles` - 创建角色
  - PUT `/api/roles/:id` - 更新角色
  - DELETE `/api/roles/:id` - 删除角色
  - POST `/api/roles/:id/permissions` - 分配权限给角色

### 3.3 用户权限路由
- **扩展用户路由** (`src/routes/userRoutes.ts`)
  - GET `/api/users/:id/permissions` - 获取用户权限
  - POST `/api/users/:id/roles` - 分配角色给用户
  - POST `/api/users/:id/permissions` - 分配直接权限给用户
  - PUT `/api/users/:id/dataScope` - 更新用户数据权限范围

## 实施要点

### 兼容性保证
- 保留现有 `role` 字段（0, 1, 2）
- 新旧系统并行运行
- 逐步迁移用户到新系统

### 安全性保证
- JWT 仅存储 userId
- 权限信息存储在 Redis
- 实现权限缓存失效机制
- 添加随机 TTL 防止缓存雪崩

### 性能优化
- 使用 Redis 缓存权限
- 添加数据库索引
- 实现权限预加载
- 支持批量权限查询

### 可扩展性
- 支持动态权限定义
- 支持自定义角色
- 支持数据权限范围
- 支持权限通配符
