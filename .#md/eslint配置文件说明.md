# ESLint 配置文件说明

## 1. 两个配置文件的区别

### 1.1 配置格式与版本

| 特性 | `eslint.config.mts` | `.eslintrc.json` |
|------|---------------------|------------------|
| **配置系统** | 新配置系统（ESLint v8.21.0+） | 旧配置系统（传统） |
| **文件格式** | TypeScript ES 模块 | JSON 格式 |
| **导入方式** | `import` 语句 | `extends` 字段 |
| **配置结构** | 数组形式，支持多配置对象 | 对象形式，单配置对象 |
| **TypeScript 支持** | 原生支持 TypeScript | 需要额外配置 |
| **动态配置** | 支持条件逻辑和动态导入 | 静态 JSON，不支持逻辑 |

### 1.2 配置内容分析

#### eslint.config.mts（新格式）
- 使用 `import` 语句导入插件和配置
- 配置是数组形式，支持多个配置对象
- 每个配置对象可以通过 `files` 字段指定适用文件
- 支持更灵活的配置组合和覆盖
- 直接使用 TypeScript 编写，类型安全

#### .eslintrc.json（旧格式）
- 使用 `extends` 字段继承配置
- 配置是单一对象，所有规则全局适用（除了 overrides）
- 依赖 `.eslintignore` 文件或 `ignorePatterns` 字段忽略文件
- 静态 JSON 格式，不支持动态逻辑

## 2. 为什么会同时存在

项目中同时存在两个 ESLint 配置文件可能有以下原因：

### 2.1 迁移过渡
- 项目正在从旧配置系统迁移到新配置系统
- 开发团队可能在测试新配置格式，尚未完全切换
- 保留旧配置文件作为备份或兼容旧工具

### 2.2 工具兼容性
- 某些旧版本的开发工具或 CI/CD 流程可能只支持旧配置格式
- 新配置系统需要 ESLint v8.21.0+，如果项目中存在多个 ESLint 版本，可能需要兼容

### 2.3 配置策略差异
- 可能用于不同环境或不同类型的文件（虽然这种情况更适合在单一配置文件中处理）

## 3. ESLint 配置文件的优先级

ESLint 会按照以下顺序查找配置文件：
1. `eslint.config.js` / `eslint.config.mjs` / `eslint.config.mts`
2. `.eslintrc.js` / `.eslintrc.cjs` / `.eslintrc.yaml` / `.eslintrc.yml` / `.eslintrc.json`
3. `package.json` 中的 `eslintConfig` 字段

**注意**：如果同时存在多个配置文件，ESLint 只会使用找到的第一个配置文件，不会合并它们的配置。

## 4. 建议

### 4.1 统一配置文件
- 建议选择一种配置格式并统一使用，避免混淆
- 新配置格式（`eslint.config.mts`）更现代、灵活，推荐使用

### 4.2 移除冗余配置
- 如果确认新配置文件已完全覆盖旧配置的功能，建议移除旧的 `.eslintrc.json` 文件
- 可以通过运行 ESLint 检查确认配置是否正常工作

### 4.3 更新 ESLint 版本
- 确保使用 ESLint v8.21.0+ 以充分利用新配置系统的优势
- 更新相关插件以支持新配置格式

## 5. 检查当前项目的 ESLint 配置使用情况

可以通过运行以下命令查看 ESLint 实际使用的配置：

```bash
npx eslint --print-config .
```

该命令会输出 ESLint 实际应用的配置，帮助你确认哪个配置文件正在被使用。
